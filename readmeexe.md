# Pipeline de Streaming (Kafka + Neon)

Este módulo configura y despliega un pipeline completo de streaming utilizando Docker. Con un solo comando se levanta la infraestructura local de Kafka, se crean los tópicos necesarios, se aplican las migraciones de base de datos en Neon y se inicializan los servicios del productor y el consumidor.

## ⚙️ Configuración Inicial (`.env`)

Crea o edita tu archivo `.env` en la raíz del proyecto. Solo necesitas configurar las siguientes dos variables de entorno con las credenciales de Neon:

```env
NEON_DATABASE_URL=postgresql://app_writer:TU_CLAVE@ep-xxxx-pooler.c-6.us-east-2.aws.neon.tech/hospedaplus?sslmode=require
NEON_OWNER_URL=postgresql://hospedaplus_owner:TU_CLAVE@ep-xxxx.c-6.us-east-2.aws.neon.tech/hospedaplus?sslmode=require&channel_binding=require
```

## 🚀 Despliegue Local

Para construir las imágenes e iniciar todos los servicios en segundo plano, ejecuta el siguiente comando en tu terminal:

```bash
docker compose up -d --build
```

### 🛑 Comandos de Control
*   **Detener el pipeline:** `docker compose stop` (los contenedores se pausan sin perder el estado).
*   **Reanudar el pipeline:** `docker compose start` (retoma la ejecución de los servicios pausados).

## 📊 Verificación y Monitoreo

Existen tres métodos para comprobar que el flujo de datos está funcionando correctamente:

### 1. Estado de los Contenedores
Verifica el estado actual de los servicios ejecutando este comando (en PowerShell o Bash dentro de la carpeta del repositorio):

```bash
docker compose ps -a
```
*   **`kafka-init` y `neon-migrate`**: Deben mostrar el estado **Exited (0)**, lo que indica que completaron sus tareas de configuración exitosamente.
*   **`producer` y `neon-consumer`**: Deben mostrar el estado **Up**, indicando que están activos y procesando datos.

### 2. Logs en Tiempo Real
Para visualizar la actividad del productor y del consumidor de forma continua, ejecuta:

```bash
docker compose logs -f producer neon-consumer
```
*   En el **`producer`** verás métricas como: `Streaming progress: sent=... peak=15 ev/s`.
*   En el **`neon-consumer`** confirmarás la persistencia con: `Neon ledger write confirmed ... inserted=True`.
*   *Para salir de la vista de logs sin apagar los servicios, presiona `Ctrl + C`.*

### 3. Consultas en la Consola de Neon
Ingresa al **SQL Editor** de Neon, selecciona la rama **dev** y ejecuta las siguientes consultas para auditar los datos guardados:

*   **Conteo de eventos por tipo:** (Los números deben incrementar si repites la consulta tras un minuto)
    ```sql
    SELECT event_type, count(*) 
    FROM streaming.reservation_event_ledger 
    GROUP BY 1 
    ORDER BY 2 DESC;
    ```

*   **Ver los últimos 20 eventos procesados:**
    ```sql
    SELECT received_at, event_type, hotel_id_payload, reservation_id
    FROM (
        SELECT *, payload->>'hotel_id' AS hotel_id_payload 
        FROM streaming.reservation_event_ledger
    ) t
    ORDER BY received_at DESC 
    LIMIT 20;
    ```
*   *Alternativa visual:* Puedes ir directamente a la sección de **Tables**, seleccionar el esquema `streaming` y examinar la tabla `reservation_event_ledger`.

## 🌐 Opciones de Despliegue Permanente (Producción)

Si requieres que el pipeline permanezca activo 24/7 de forma definitiva, existen dos alternativas de arquitectura:

| Característica | Opción 1: Entorno de Demo (Rápido) | Opción 2: Arquitectura v3 (Robusto) |
| :--- | :--- | :--- |
| **Infraestructura** | Una instancia pequeña de AWS EC2. | AWS ECS Fargate + AWS MSK (Managed Kafka). |
| **Despliegue** | Clonar repo, configurar `.env` y correr Docker Compose. | El productor y consumidor corren como servicios independientes en ECS. |
| **Persistencia** | Contenedores con reinicio automático de Docker. | Infraestructura gestionada y escalable de AWS. |
| **Seguridad** | Archivo `.env` local en la máquina virtual. | URLs y credenciales de Neon resguardadas en **AWS Secrets Manager**. |

> **💡 Soporte:** Te sugerimos iniciar con la **Opción 1** para validar el comportamiento en la nube y migrar a la **Opción 2** una vez que tengan aprovisionado el clúster de MSK. Si observas algún error en los logs (marcado en rojo), cópialo y compártelo conmigo **eliminando previamente cualquier URL o contraseña**.
